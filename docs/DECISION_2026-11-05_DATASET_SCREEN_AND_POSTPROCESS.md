# Decision: dataset quality, screen capture, segmentation, and postprocessing (2026-11-05)

## Requirements and target

FR-03/08/17/18/22/24/25/32; V-CAP-04 and the separate robot-learning gate. The owner chose **LeRobot v3** as the first future robot-policy target. Its episode format requires synchronized camera frames, measured robot observations/state, actions, timestamps, embodiment and feature metadata. VEYTAC's current phone/screen capture is a VEYTAC observation ZIP, not LeRobot v3. `robot_state` and `robot_action` stay null. No conversion may infer them from video or hand points.

## Changes

- Desktop screen capture uses the same session consent, MediaRecorder chunk upload, microphone, frame observations, voice questions, review, and private library flow as camera capture. `getDisplayMedia` is called in the Start click before API requests. The screen has no on-device MediaPipe object tracker in this slice; bounded frame observations still run. Browser and OS support are runtime gates. The screen stream stops on Stop while the camera preview resumes when available.
- Frame snapshots record their actual JPEG dimensions. Media chunks carry recording elapsed time and detected gaps, and the observation ZIP includes source type, chunk hashes/timing, masks, labels and notes. The quality endpoint reports missing clocks, incomplete media, mock/failed observations, mask decode count, reviewed decisions and permission. A `CANDIDATE` status means local evidence checks passed; it is not model training validation.
- SAM SVG paths are rendered as translucent colored object/person masks on live and replay frames when decoded geometry exists. Without decoded geometry, the UI shows a box and labels it as a candidate. These are sampled masks, not continuous identity tracks or depth estimates. Meta's documented confidence option is under `metadata` as a string.
- The AI dataset JSONL exports only the latest approved decision revision after its observation evidence resolves to a proposed source observation and the quality gate passes. Each row includes a neutral `input_text`/`output_json` pair, source observation ID, session split group, original expert language, reviewer and full target record. New live decisions inherit the triggering observation's evidence reference and recording elapsed timestamp. Recording and training permissions are separate. Camera and screen exports require an explicit owner declaration of training rights and source origin. The declaration is an attestation, not independent rights verification. Human inspection, redaction, multi-session splitting and a provider-specific adapter remain necessary before any training run.
- Postprocessing is an explicit, bounded service run with media integrity, visual evidence, dialogue linking, human review and format gates. The run saves a source digest, unreviewed labels, unanswered questions and unresolved observation uncertainty as a review queue. Repeating it over the same source gives the same digest. It makes no paid calls and creates no synthetic expert answer, tool trace or robot action. Code-agent harness training stays blocked until reviewed tool calls, outcomes and executable evaluations are captured. Training jobs and generative multi-agent processing are not enabled by this decision.
- Brief and answered-question acknowledgments use the selected English, Japanese or Mandarin voice, resume listening after speech, and do not alter the expert answer.

## Evaluation boundary

Current ZIP can be research input for visual perception only after permission, source review, timing checks and a model-specific loader. Approved JSONL can be a candidate for specialist decision extraction after multi-session train/validation splitting, rights/privacy review and target-model validation. A single phone or screen session cannot prove robot action training, code-agent competence, or model improvement. No paid inference, training job, or deployment was authorized for this change. Screen capture on iPhone Safari, actual SAM mask quality, cross-browser replay timing, and spoken dialogue on a device require separate real evidence.

The latest stored camera session at inspection time (`ses_[redacted]`) had 32 contiguous chunks (13,408,507 bytes), all matching stored size and SHA-256; a seekable 62.955-second playback file existed. It had seven successful live observations, nine on-device track samples, four unreviewed expert notes, a saved task brief, and separate training permission. It had **zero** saved question, answer, decision, SAM mask, or chunk-timing records. The recording is usable as a visual research source after review, but it is not a reviewed SFT dataset or robot policy dataset. Its observations had uncertainty text, yet the question proposer sent the scene description as the missing fact; this was changed to the stored uncertainty and question-proposal diagnostics were added. A new consented device run is needed to prove this change produces a useful spoken question.

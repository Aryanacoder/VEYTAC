# Decision 0004 — single-screen live UI and question gate (2026-11-03)

Owner direction: make the live app a single glass and blue-white camera screen with Start, Stop, and Mute; show spoken questions and answers on the video; animate a red observing scan; favor low latency. The owner also pointed to Fireworks and Baseten for fast inference.

1. Start presents separate capture and external-processing consent for each session. Once both are granted, it starts capture and explicitly opens a 30-second question window. While capturing, Start can open another 30-second window when the human considers it safe. Mute revokes the window, silences microphone tracks, and defers any outstanding question. Unmute opens a fresh 30-second window. Stop ends capture and the window. No model can open or renew a window. This keeps FR-01 and FR-11's human gate despite the three-control interface.
2. A first frame is observed as soon as the video is ready, even if the on-device tracker detects no hands. Subsequent model frames follow tracked changes, with a timed fallback if tracking is unavailable. Local checks run once per second. The red scan is CSS only and is explicitly an activity cue, not proof of model understanding. Question text and recognized answer appear over the live video; review follows below the stage after Stop.
3. The browser voice socket uses the page origin's `ws:`/`wss:` protocol, and Vite proxies WebSocket upgrades to the API. The relay has a 2.5-second connection timeout before browser speech fallback. No secret enters the browser.
4. The active observation and question adapters still target Meta. Repository Fireworks code currently plans/launches Glimmer SFT, and Baseten code plans a deployment; neither is an implemented live inference adapter. Do not silently switch runtime providers. Adding either requires an explicit provider contract, model/license and data-rights review, budget accounting, consent notice update, timing comparison, and tests. No Fireworks or Baseten request was made here.
5. Consent in this prototype records the local `usr_owner` actor supplied by the client. Workplace authority, expert identity, and real-device consent evidence still need human validation before a public or customer demo. This UI does not grant training or publication permission.

Requirement focus: FR-01, FR-02, FR-11, FR-24, FR-28; NFR-02 and NFR-08 remain separate release checks. Verification of this change is offline/mock only until a consented real-provider and device run records latency, spend, and question/answer evidence.
